# Walk in home DTX

Walk in home 2024 の「共有ファイル」形式。テキストだが仕様書はない。
ここの内容は、Walk in home が出力した DTX と、ユーザーが Walk in home 上で直した DTX を比べて分かったこと。

## 使い方（基本の流れ）

1. 図面から間取りを読み取り、**plan JSON** を書く（書式は下の「plan JSON」）
2. `python3 scripts/dtx.py build plan.json OUT.dtx`
3. `python3 scripts/dtx.py check OUT.dtx` と `summary OUT.dtx` で確認
4. ユーザーが Walk in home で直した DTX が返ってきたら
   `python3 scripts/dtx.py diff 自分の.dtx 直した.dtx` で差分を見て、下の「ルール」に足す。
   直した DTX は `extract` で plan JSON に戻せる（往復で同じ DTX に戻ることを確認済み。連窓・ポーチも対応）。

ひな形 `templates.json` は、ユーザーが直した DTX から取ったレコード。見本にない種類の建具などは作れない（推測でコードを作らない）。

## ファイルの決まり

- 文字コード **Shift_JIS (cp932)**、改行 **CRLF**、固定幅。整数は 5 桁右詰め、実数は 10 桁・小数 2 桁。
- 1 行目 `DTX Version  918 …`、続いて `[XXXX]` セクションが決まった順に約 140 個並び、最後に `EOF`。
  セクションは中身が空でも省略しない（順番も変えない）。`templates.json` の skel が並び順そのもの。
- セクション見出し `[HEYA]   17  301      \ 部屋 ---` の数字は「件数」「行数」。
  **TATE（建具）だけ行数を「実際の行数 − 件数」で数える。**
- 各レコードは `    0    0    0 `（末尾にスペース）の行で始まる。
- 座標は mm。**Y は上（北）が大きく、図面上端を 0 にして下へマイナス**で書く例が多い。X は右へプラス。
- 通り芯は 910 モジュール。KANX（矩計）に階高・床高・天井高（1階 2896 / 36 / 2400 など）。

## ルール（ユーザーの修正から分かったこと）

### 全体
- **多角形の点は必ず反時計回り（Y 上向きで見て）**。部屋・畳・外周・部分床・階段・ポーチすべて。
  時計回りだと Walk in home で畳が敷かれない・部分床（土間）が出ない・階段がおかしくなる。
  `build` が自動で反時計回りにそろえる（始点はそのまま）。

### 部屋 HEYA
- 2 行目: `階, 点数, 種類コード, 0, 0, 0, 1, 0`
- 種類コード: 1=玄関・土間 / 2=廊下・階段・ホール以外の通路 / **3=和室** / 4=洋室・LDK・台所・ホール / 6=浴室 / 7=洗面 / 8=トイレ / 13=収納（押入・物入も）
- 3 行目: `床高, 天井高, 0, 60, 0`。玄関・土間は床高 -180 で 4 番目 0。浴室は 4 番目 0・5 番目 5。
- 名前の行と表示の行:
  - LDK・台所・和室・洗面・浴室・勝手口は表示行 `（&J 帖）` で帖数を出す
  - 玄関・ホールは表示 `なし`
  - 便所・収納・押入・物入は表示行を空にする
  - **廊下や階段まわり、出窓の張り出し部分など名前を出さない部屋は、名前も `なし`**
- 点のあとの行の最後が `2`=居室（LDK・台所・和室・ホール・張り出し部）/ `3`=非居室。
- 部屋は台所の L 字など実際の形どおりの多角形にする（点数は自由）。曲面（弓形出窓）は折れ線で近似した部屋にする。
- 和室には **TATA（畳）** を部屋と同じ範囲で入れる。

### 壁 KABE
- 2 行目 2 番目が壁の種類: 1=普通の壁 / 2=下がり壁（3 行目先頭が下端高さ 2000）/ 3=腰壁（3 行目 2 番目が高さ 1100）
- 外壁は 4 行目が `10, 24, …, 10, 70`、内壁は `10, 70, …, 10, 30`。
- 壁は交点ごとに分ける。建具が付く位置で壁を切る必要はない。
- **外壁は建物を反時計回りに回る向き**（進む向きの左手が室内、右手が屋外）で入れる。
  上の壁は右→左、左の壁は上→下、下の壁は左→右、右の壁は下→上。
  逆向きだと Walk in home が屋外側を取り違え、その壁の窓が「外に接している」判定にならない。
  `build` が exterior の壁を自動でこの向きにそろえる（部屋の内側を左手に見る向き）。

### 建具 TATE
- 2 行目: `階, 建具コード, 吊元(±1), 0, 0, 窓なら1, …, 41=窓/31=戸, …`
- 3 行目: `上端高, 開口高, 出幅(出窓の窓のみ)`。4 行目先頭が開口幅。
- 7 行目: 始点 X, Y, 終点 X, Y（壁芯上）。
- 13 行目 5 番目が **建具番号**、14 行目が **記号**。記号ごとに 1, 2, 3 … と振る（`build` が自動で振る）。
  記号: AW=外部窓 / AD=外部ドア（勝手口など）/ WD=室内ドア・引戸 / WF=襖
- 21 行目は仕様メモ（`玄関ﾄﾞｱ`、トイレ・浴室の窓は `型板`、襖に `透明` など）。
- 外部建具（AW/AD）は 46 行、室内建具（WD/WF）は 44 行。ひな形がこれを持っている。
- 使える種類（plan JSON の kind）:

  | kind | コード | 名前 | 記号 | 用途 |
  |---|---|---|---|---|
  | window_slide | 1 | 引違い窓 | AW | 一般の引違い窓・掃出し窓 |
  | window_vert | 13 | 縦滑り出し | AW | トイレ・浴室・洗面の小窓 |
  | window_bay | 902 | 引違い窓(2枚) | AW | 出窓に付く窓（depth=出幅 400） |
  | door_ext | 104 | 片開きﾄﾞｱ | AD | 勝手口 |
  | door_side | 105 | 片開きﾄﾞｱ(片袖) | WD | 玄関ドア（高さ 2330、spec `玄関ﾄﾞｱ`） |
  | door_in | 104 | 片開きﾄﾞｱ | WD | 室内ドア |
  | sliding_in | 112 | 引違い戸(2枚) | WD | 室内の引違い戸 |
  | fusuma | 101 | 引違い戸(2枚) | WF | 和室・押入の襖 |
  | opening_frame | 114 | 開口枠 | WD | 戸のない開口 |

  | combo_fix | 6 | FIX窓 | AW | 連窓の FIX 側 |
  | combo_vert | 13 | 縦滑り出し | AW | 連窓の縦滑り出し側（番号は FIX のマイナスが自動で付く） |

  連窓（例: 居間の FIX＋縦滑り出し）は combo_fix と combo_vert を続けて書き、両方に
  `"combo": {"p1": 全体の始点, "p2": 全体の終点, "top": 上端高, "width": 全体の幅}` を付ける。
  図面に「HK」などと書いてあっても、FIX と縦滑り出しの組み合わせなら連窓にする。
- 弓形出窓の両端の小窓は縦滑り出し（幅 300、高さ 1000、上端 2000）を弓の端の辺に置く。
- 造作の出窓は **ZDEM（造作出窓）** に `上端高, 高さ, 出幅(455)` と壁芯上の始点・終点を入れ、
  その出窓に付く窓は壁芯から出幅だけ外へずらした線上に置く（例: 上端の壁 Y=0 なら Y=455）。

### 寸法線 SUNP
- 2 行目 `階, 1, 0, 0, 0, 向き(±1)`、3 行目 `P1, P2, P3`（6 数）。
- P1→P2 が測る区間（横は右→左、縦は上→下の順）。P3 が寸法線を引く位置。
- 上・左は向き +1、下・右は -1。区切り寸法は外壁から 1365、全体寸法は 1820 外に置く例が多い。
- 外壁から張り出す部分（ポーチ・下屋など）があるときは、その外側の線を基準にする。

### その他
- **GAIS（外周領域）**: 階ごとに建物外周。2 階側に吹抜・階段の領域が入ることがある。
- **AGAR（上り框）**: 玄関・勝手口など床に段差がある境目に線で入れる。
- **KAID（室内階段）**: 範囲 4 点と段数（例 11 段）。**最初の辺が上り口**（例: 5460 側から上がるなら
  `[[5460,-4095],[5460,-3185],[2730,-3185],[2730,-4095]]`）。長さは段数 × 踏面（11 段で 2730 程度）。
  階段の上が居間などに掛かっていても、階段の範囲は全長で入れる。
  **KCUT（階段破断線）** と、**2 階の GAIS に階段の範囲（吹抜）**も一緒に入れる。
- **BYUK（部分床）**: 勝手口の土間など、部屋の一部だけ床高が違うところ（例 -200）。
- **PORC（ポーチ・土間）**: 玄関ポーチは種類 1、掃出し窓や勝手口の前のステップは種類 2。高さ 150。
  玄関ポーチは玄関のへこみを囲む形にし、袖壁の外まで広げる。
- **袖壁**: ポーチ脇の短い壁（例: 玄関ポーチの両側 455）は普通の内壁として入れる。
- POIN・LINE・CIRC・TEXT・INTE（家具）・SETU（設備）はユーザーが Walk in home で描き足すもの。
  作る必要はない（`build` では空になる）。

座標はすべて DTX の座標（Y は上端 0 から下へマイナス）。

  "walls": [{"floor": 1, "kind": "normal", "exterior": true, "p1": [0, 0], "p2": [2730, 0]},
            {"kind": "hang", "bottom": 2000, "p1": [6370, -1820], "p2": [6370, -910]},

  "fittings": [{"kind": "window_slide", "p1": [3640, 0], "p2": [5460, 0], "width": 1620, "height": 600, "top": 1850},
               {"kind": "door_in", "hinge": 1, "p1": [3640, -4095], "p2": [3640, -5005], "width": 690, "height": 2000, "top": 2000},

## 注意
- DTX を作るところで止める。喜多ハウジングの図面（kita-zumen）まで作るのは、ユーザーが頼んだときだけ。
- Walk in home で読み込めるかは、最終的にユーザーに試してもらう。直した DTX が届いたら差分を見てこのファイルのルールを更新する。
- 図面の読み取りでよく間違える点: 出窓（造作出窓か窓のみか）、玄関と下足入の境、台所の形（L 字）、押入・物入の範囲、階段の範囲。迷ったらユーザーに確認する。
